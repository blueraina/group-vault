# 维护时间线自动更新

仓库已经配置 GitHub Action：有人直接 push 到 `main` 且修改了 `content/` 内的笔记时，Action 会自动更新 `content/维护时间线.md`，再把这篇时间线提交回 `main`。

为了让 Cloudflare Pages 只构建一次，需要在 Cloudflare Dashboard 里设置 Build watch paths：

```text
Include paths:
content/维护时间线.md
```

不要给 GitHub Action 的自动提交添加 `[skip ci]` 或 `[CF-Pages-Skip]`。

完成后流程是：

```text
群友修改 content/ 笔记并 push 到 main
Cloudflare 检查到没有改 content/维护时间线.md，因此跳过部署
GitHub Action 自动更新 content/维护时间线.md
Cloudflare 检查到维护时间线变化，因此部署一次
```

如果之后只修改主题、Quartz 配置、脚本或非 `content/维护时间线.md` 的文件，Cloudflare 不会自动部署。那种维护类改动需要手动触发一次部署，或临时调整 Build watch paths。
